George (Asda) image savings bookmarklet

A one-click browser bookmark that scans any george.com page, re-fetches every asda.scene7.com image through Cloudinary with f_auto / q_auto:eco, and overlays the byte savings in green directly on each image.

Drag this button to your bookmarks bar 👇

⬇ Cloudinary Savings

Clicking it here won't do anything useful — it needs to run on a George page.

How to install it

Chrome / Edge / Firefox (easiest)

  1. Show your bookmarks bar if it's hidden: ⌘⇧B on Mac, Ctrl+Shift+B on Windows.
  2. Drag the green ⬇ Cloudinary Savings button above onto the bookmarks bar.
  3. That's it — the bookmark is now a mini script rather than a link.

Safari

Safari won't let you drag a bookmarklet straight to the Favourites bar, so add it manually:

  1. Show the Favourites bar: View → Show Favourites Bar.
  2. Bookmark any page (⌘D) into Favourites and name it Cloudinary Savings.
  3. Open Bookmarks → Edit Bookmarks, right-click your new bookmark and choose Edit Address.
  4. Copy the code from the box below and paste it in as the address, then press Enter.

Manual install (any browser)

  1. Copy the code below.
  2. Create a new bookmark and paste the code into the URL / Address field (not the name field).
  3. Save. Don't paste it into the address bar — most browsers strip the javascript: prefix when you type there.

How to use it

  1. Go to any george.com page with product imagery — a category listing works best.
  2. Scroll down so the lazy-loaded images actually load. The bookmarklet only sees images already in the DOM.
  3. Click the ⬇ Cloudinary Savings bookmark.
  4. Each Scene7 image gets a bright green badge with its saving, and a summary panel appears bottom-right with the page total.
  5. Open the console (⌘⌥J / F12) for the full per-image breakdown with both URLs.
  6. Use Hide overlays in the summary panel to flip between the clean page and the annotated one while presenting.

Good to know

  • Sizes come from the content-length header on a HEAD request, so any image served without that header is skipped from the totals.
  • The Cloudinary side uses the patrickg cloud in fetch mode. First run on a new image is a cache miss, so the numbers are stable but the fetch can be a little slow.
  • Savings reflect format and quality only (f_auto, q_auto:eco) — no resizing. Adding responsive sizing would push the numbers considerably further, which is a good thing to say out loud in the room.
  • The page's own CSP can block the Cloudinary fetches on some sites. If every image comes back empty, check the console for CSP errors.
  • Refresh the page to clear all the overlays.
